# 05 — План реалізації та статус

> Оновлено 2026-11-15 за кодом і завершеними прогонами. Зміна документації не змінює версію exe.

## Поточний статус

**v0.4.0, x64 Release.** Одиночний PNG, орбітальний перегляд, ImGui, 3D/2D-черги,
SMD-моделі та аналіз порожніх PNG реалізовані. Пакет із процесом на файл,
CSV/логами/оглядами працює через `scripts/check-gfx.py`; `--list` у exe лише читає список.

Контрольний прогін: **43 VISIBLE / 5 EMPTY** із 48. Розширений: **212 VISIBLE /
28 EMPTY** із 240. В обох `FAIL=0`, `TIMEOUT=0`; разом перевірено 265 різних
файлів із 9019. `VISIBLE` є піксельною перевіркою, а не підтвердженням точності гри.
Повний протокол і команди — [07-gfx-audit.md](07-gfx-audit.md).

## Відкриті питання (розв'язати під час реалізації)
1. ECM потребує справжнього `CECModelMan`, життєвого циклу та клієнтських проходів рендеру; його getter досі `nullptr`.
2. Warp, сценарії навичок, залежність від руху власника й текстові емітери потребують окремого контексту/перевірки; порожній PNG не доводить пошкодження ассета.
3. Великі 2D-сцени та нульові AABB: центрування/запасна відстань не завжди дають придатний огляд. Накопичення кроків може пересвічувати зображення.
4. Перевірити повноту залежностей і часткові пропуски компонентів навіть для `VISIBLE`.
5. Завершити звільнення ресурсів рушія на всіх шляхах перед багаторазовим використанням preview в одному процесі.

Вирішені питання: `TexFile` використовує `Gfx\Textures`; SMD — `gfx\Models`;
PNG кодується WIC; окремі 2D-черги підключені. Джерела — [API-референс](03-gfx-api-reference.md).
