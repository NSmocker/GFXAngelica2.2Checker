# 01 — Специфікація проєкту GFXAngelica2.2Checker

## 1. Призначення

Утиліта для **перевірки та візуального рендеру** GFX-ефектів клієнта Perfect World
на движку **Angelica 2.2** (Direct3D 9). Користувач готує текстовий файл зі списком
шляхів до `.gfx`, утиліта послідовно завантажує кожен ефект, рендерить його і
фіксує результат (картинка + статус).

Стан на **2026-11-15**, версія exe **0.4.0**: одиночний offscreen PNG, інтерактивний
перегляд з орбітальною камерою та ImGui-статистикою, 3D/2D-рендер, завантаження SMD,
self-test і читання txt-списку. Пакетна перевірка реалізована окремим
`scripts/check-gfx.py`: процес на файл, аналіз пікселів, CSV, PNG та логи.
Вбудований у exe цикл txt → render і розгорнутий звіт залежностей ще заплановані.

## 2. Вхід

**Файл-список** (наприклад `gfx_list.txt`):
- по одному повному або відносному шляху до `.gfx` на рядок;
- рядки, що починаються з `#` або `;` — коментарі, порожні рядки ігноруються;
- кодування рядків: ANSI/**GBK** (імена ассетів китайські); утиліта має терпимо приймати і UTF-8 з BOM (конвертуючи у ANSI).

Приклад структури списку (імена умовні):
```
# список для перевірки
B:\Git\PW146RUUnpackedAssets\gfx\npc\example.gfx
B:\Git\PW146RUUnpackedAssets\gfx\gfx\example2.gfx
```

**Запланований інтерфейс пакетного чекера (ще не реалізований):**
```
GFXAngelica2.2Checker.exe <list.txt> [options]
  --root <dir>      корінь ассетів (де лежить папка gfx\)       [default: авто-визначення зі шляхів]
  --out <dir>       каталог для PNG-знімків                     [default: .\out]
  --report <file>   CSV-звіт                                    [default: .\report.csv]
  --frames <N>      скільки кадрів проганяти для кожного ефекту [default: 10]
  --window [path]   віконний режим превʼю (один ефект або список по PgDn)
  --rt <WxH>        розмір offscreen render target              [default: 512x512]
  --verbose         деталізований лог залежностей (текстури, моделі, звуки)
```
**Реалізовані команди:**
```
GFXAngelica2.2Checker.exe --help
GFXAngelica2.2Checker.exe --version
GFXAngelica2.2Checker.exe --self-test --root <asset-root>
GFXAngelica2.2Checker.exe --list <list.txt>
GFXAngelica2.2Checker.exe --preview --root <asset-root> --gfx <path> [--output preview.png] [--width 512] [--height 512] [--frames 10]
GFXAngelica2.2Checker.exe --interactive --root <asset-root> --gfx <path> [--width 512] [--height 512]
```
`--output` задає PNG-файл; за замовчуванням це `preview.png` у теці запуску.
Відносні шляхи `--output` також рахуються від теки запуску.
`--self-test` перевіряє AFI та створення об'єктів готових бібліотек без D3D-пристрою.
`--list` читає і друкує записи; не рендерить їх, не перевіряє існування залежностей
і не застосовує `--root`. Для preview корінь задається явно.

`--interactive` відкриває видиме вікно з таким керуванням:
- розмір вікна можна змінювати стандартною рамкою Windows; після завершення resize
  підлаштовуються D3D backbuffer, viewport, перспектива камери та 2D-viewport GFX;
- затиснути **середню кнопку миші (MMB)** й перетягувати — орбіта навколо центра AABB ефекту;
- **W** — ближче, **S** — далі; центр і кути огляду при цьому зберігаються;
- **Frame effect** у панелі — повернути початкове кадрування;
- **Esc** поза захопленням клавіатури ImGui або закриття вікна — завершити перегляд.

Курсор вільний, A/D і Shift не керують камерою. Кути біля полюсів і відстань
обмежені, щоб камера не переверталася і не проходила крізь центр.
Введення, захоплене ImGui, не передається камері.
Одноразовий `--preview` зберігає PNG без панелі статистики.
На інтерактивне вікно можна перетягнути один `.gfx` із `<root>\gfx\`; він замінить
поточний ефект, оновить статистику й поверне камеру до нового. Якщо завантаження
поверне помилку або C++-виняток, попередній ефект лишається; SEH-збої поки завершують процес.
Для запуску подвійним клацанням доступні `run-interactive.bat` та `run-preview.bat`.
Обидва приймають шлях до GFX як перший аргумент або запитують його; preview-батник
також приймає вихідний PNG другим аргументом і за замовчуванням пише `preview.png`
поруч із батником.

### 2.1 Реалізований пакетний запуск

```powershell
python scripts\check-gfx.py --out build\gfx-audit\sample-new --limit 240 --seed 20261115 --retry-frames 100
```

Потрібні Python 3 і Pillow. Скрипт обирає файли з дерева `<root>\gfx`, або приймає
`--manifest <json>` — масив шляхів відносно цієї папки. Це окремий інтерфейс,
який не читає txt-список із `--list`. Параметри, вихідна структура й повторення
прогону описані в [07-gfx-audit.md](07-gfx-audit.md).

## 3. Вихід

### 3.1 PNG-знімки
Для пакетного режиму планується знімок останнього кадру: `<out>\<номер>_<ім'я файла>.png`
(ім'я файла з GBK -> перетворюється у безпечну ASCII-форму, наприклад транслітерація або hash).
У реалізованому одиночному preview зберігається буфер після N кроків по 50 мс.
Як у референсі ICL, буфер очищується один раз перед циклом, тому зображення може
містити накопичення кількох кроків анімації. Альфа PNG примусово дорівнює 255.
`PlaySpeed` ефекту змінює його внутрішній час: 100 кроків — 5000 мс поданого часу,
але не обов'язково 5000 мс у `GetTimeElapse()`.
Перед записом C++ рахує ненульові RGB-пікселі та максимальний канал; порожній
кадр логується як `EMPTY`. Успішний запис PNG, зокрема порожнього, має exit code 0.
Пакетний скрипт незалежно перевіряє збережений PNG через Pillow.

### 3.2 Статистика у вікні
Панель **GFX statistics** показує ім'я файлу (GBK → UTF-8), стан відтворення,
2D/3D, готовність ресурсів, загальну й активну кількість елементів, виділені
частинки й частинки, відрендерені цього кадру, draw calls, примітиви, час ефекту,
швидкість, FPS, CPU-час tick/render, відстань і кути камери.
У **Effect details** — початковий AABB, масштаб, альфа, версія GFX, видимість та циклічність.
Лічильники менеджера охоплюють поточну GFX-сцену, включно з вкладеними ефектами;
виділені частинки не означають кількість живих частинок. CPU render — час подання
команд, а не GPU-таймінг. `Resources: ready` не є перевіркою повноти залежностей.

### 3.3 CSV-звіт пакетного скрипта

Поточний `report.csv` — UTF-8 з BOM, роздільник `;`:
```
idx;file;status;exit_code;seconds;frames;attempts;nonblack;maximum;png
```

- `VISIBLE`: exit code 0 і хоча б один ненульовий RGB-піксель; `EMPTY`: exit code 0 і всі RGB нульові.
- `FAIL`: невдалий запуск/код виходу або відсутній PNG; `TIMEOUT`: перевищено час процесу.
- `frames`, `nonblack`, `maximum`, `png`, `exit_code` описують останню спробу; `attempts` — 1 або 2, `seconds` — сумарний час запусків із очікуванням.
- PNG-шлях відносний до вихідної теки; перша спроба та її логи зберігаються навіть після повтору.

Ці статуси не перевіряють відповідність грі, повноту залежностей чи причину порожнього
кадру. Повна схема майбутнього вбудованого чекера ще не реалізована:
```
idx; file; status; elements; textures_loaded; models_loaded; sounds; aabb_size; frames_ms; png; message
```
- `status`: `OK` | `LOAD_FAIL` | `RENDER_FAIL` | `SKIPPED` | `EXCEPTION` (перехоплене SEH-виняток)
- `message`: короткий опис помилки (з логу движка), для EXCEPTION — код винятку.

### 3.4 Лог
`a_LogOutput` перенаправлено в `checker.log` біля exe. Preview записує параметри GFX,
камеру/AABB, сумарні лічильники рендеру, типи й активність елементів, результат
завантаження SMD та `PNG pixels: nonblack=… total=… maximum=… status=…`.
Скрипт копіює `checker.log`, доступні `A3D.log/AF.log/AM.log`, а також stdout/stderr
в окрему папку кожної спроби; власна копія exe/DLL прогону міститься в `runtime/`.

## 4. Ключові вимоги

1. **Залежності ассетів резолвляться з кореня ассетів.** База файлової системи
   (`af_SetBaseDir`) = каталог, у якому лежить папка `gfx\` (наприклад `B:\Git\PW146RUUnpackedAssets`).
   Шлях, що передається в `A3DGFXExMan::LoadGfx`, — відносний від кореня `gfx\`
   (див. `docs/03-gfx-api-reference.md` §3.2).
2. **Точність рендеру = точність гри.** Програма є переглядачем GFX-ефектів, тому
   поведінка рендера має максимально повторювати оригінальний клієнт. Якщо для збереження
   точності потрібно копіювати оригінальні фрагменти коду/алгоритми/ініціалізацію з
   `PW_ClientSource` в цей проєкт — це допустимо і є обов'язковим при потребі.
3. **Ізоляція збоїв.** Поточний пакет запускає окремий exe для кожного файлу і повтору;
   timeout завершує дочірній процес. У самому exe діагностика SEH не відновлює рендер.
   Для майбутнього пакета в одному процесі потрібні очищення ресурсів і перевірене відновлення стану.
4. **Швидкість.** Для пакетного чекера RT невеликий (512x512), N кадрів (за замовч. 10) — як у референсі ICL.
5. **Кодування.** Проєкт у **MBCS** з явним `UNICODE` для ABI рушія. CLI і Win32-перевірки шляхів — UTF-16; вузькі шляхи рушія — GBK. ImGui отримує UTF-8. `LC_CTYPE=".936"`, `LC_NUMERIC="C"` — десяткова крапка потрібна парсеру GFX.
6. **Без змін у PW_ClientSource.** Копіюємо/адаптуємо код у власних файлах, з коментарем походження.


## 6. Відомі обмеження

- Список потрібно передавати через `--list`: позиційний `<list.txt>` поки відхиляється парсером.
- Коментар на першому рядку UTF-8-файлу з BOM помилково потрапляє до записів списку.
- Нечислові `--width`, `--height`, `--frames` можуть спричинити необроблений виняток; вводити додатні цілі числа.
- SMD-моделі завантажуються через `A3DSkinModel`; ECM-менеджер лишається `nullptr`. Сценарії навичок, звук, raytrace, тіні й shake camera не відтворюються повністю.
- Поверхня/нормаль землі використовують редакторську площину; реальної сцени гри немає. Warp-прохід і рух власника для слідів зброї не реалізовані.
- Обидві 2D-черги підключені, але кадрування великих UI-ефектів та ефектів із нульовим/неточним AABB ще потребує роботи. Накопичення кроків може пересвічувати PNG.
- Resize інтерактивного вікна виконує явний Reset D3D-пристрою; автоматичне відновлення
  після сторонньої втрати пристрою, Win32, Debug і пакет у межах одного процесу не перевірені.
- Повний набір із 9019 файлів не прогнано. Поточні результати й нерозібрані `EMPTY` — у [протоколі перевірки](07-gfx-audit.md).
